---
This isn't actually a Ruff problem — `uv add` would have failed for any new dependency. The issue is in `pyproject.toml`:

```toml
requires-python = ">=3.8"
```

This declares the project supports Python 3.8+, but your runtime dependency `requests>=2.33.0` requires Python 3.10+. The two constraints are mutually exclusive on Python 3.8 and 3.9, so uv refuses to lock.

You've been getting away with it because your existing `requirements.txt` was generated with `pip-compile` running under Python 3.12 — pip-compile only resolves for the active interpreter, so it never noticed the contradiction. uv is stricter: it resolves across every Python version your `requires-python` declares.

## The fix

Edit `~/GitHub/sonar-issue-exporter/pyproject.toml`:

```toml
# Was: requires-python = ">=3.8"
requires-python = ">=3.10"
```

Why `>=3.10` and not higher:
- **3.8** reached end-of-life October 2024 — dropping it is correct regardless.
- **3.10** is the floor `requests>=2.33.0` actually supports, so it's the minimum your project can honestly claim.
- **3.12** is what `requirements.txt` was originally compiled against. If your SonarCloud CI (`.github/workflows/sonarcloud.yml`) uses a specific Python version, bump `requires-python` to match that for tighter guarantees. I didn't see that workflow file in your Repomix archive, so I can't be more specific.
- You're locally on **3.14** (Fedora 44 is bleeding-edge as always) — no concern there.

## For one-off CLI checks right now

Use uv to run it from the project's venv without activating anything:

```fish
uv run ruff check .
```

This is the same pattern you'd use in CI (your future `.github/workflows/sonarcloud.yml` or a new `lint.yml` would run `uv run ruff check .`).

## For Zed's language server integration

Zed needs the `ruff` binary on PATH globally — it can't (cleanly) invoke `uv run` per-project from `settings.json`. The uv-native way:

```fish
uv tool install ruff
```

This installs ruff as a standalone uv-managed CLI tool, available in every shell and to every editor, decoupled from any project's venv. It lands at `~/.local/bin/ruff`, which is on PATH by default on Fedora. Verify:

```fish
which ruff
ruff --version
```

You now have **two ruff installations**:
- `~/GitHub/sonar-issue-exporter/.venv/bin/ruff` — pinned to the project's `pyproject.toml`, used by `uv run ruff` and CI
- `~/.local/bin/ruff` — the global one Zed will use

This is fine and intentional. The project pinning ensures CI reproducibility; the global one is for editor convenience. They can be different versions without issue because Ruff's CLI/LSP protocol is stable across minor versions.

If the duplication bothers you, the alternative is the system package:

```fish
sudo dnf install ruff
```

Fedora 44's ruff package is recent enough for daily use, though it may lag `uv tool install` by a few versions. Either works for Zed.

## Option A — Bump line-length to 100 (recommended)

Your longest line is 105 chars (the watch_clipboard.py comment). Most modern Python projects use 100; Black's default is 88 but almost everyone overrides it. Add to `ruff.toml`:

```toml
[format]
line-length = 100

[lint]
# (existing select/ignore)
```

Wait — `line-length` is a top-level key in Ruff, not nested under `[format]`. Correct syntax:

```toml
# Top of ruff.toml
line-length = 100

extend-exclude = [ /* ... existing ... */ ]

[lint]
# ...
```

This silences 7 of the 9 (everything ≤100 chars). The remaining 2 are:
- `export_sonar_issue.py:48` — 104-char docstring
- `watch_clipboard.py:59` — 105-char comment

For those two, either bump to `line-length = 110` (silences everything, defensible) or wrap them manually.

## Option B — Wrap them manually (most idiomatic)

For the `print()` strings, use Python's implicit string concatenation (adjacent string literals are joined at compile time, no runtime cost):

```python
# Was (98 chars):
print(
    "Note: no .env file found in current directory, script directory, or home directory.",
    file=sys.stderr,
)

# Becomes:
print(
    "Note: no .env file found in current directory, "
    "script directory, or home directory.",
    file=sys.stderr,
)
```

Same pattern for the other three `print()` calls at lines 120, 145, 302. Each is a single string literal that splits cleanly at a sentence boundary.

For the docstrings, wrap the prose at a natural phrase boundary:

```python
# Was (104 chars):
def html_to_md(html: str) -> str:
    """Basic HTML to Markdown-like text: remove tags, decode entities, replace <br> with newline."""

# Becomes:
def html_to_md(html: str) -> str:
    """Basic HTML to Markdown-like text.

    Removes tags, decodes entities, replaces <br> with newline.
    """
```

For the watch_clipboard.py comment:

## Option C — Per-line `# noqa: E501` (lazy)
